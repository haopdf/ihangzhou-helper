QUICK-START-GUIDE

📂 文化生活 📖 杭州故事

This guide provides step-by-step instructions to deploy and configure the VMware Horizon Certificate Automation solution.

📋 Prerequisites

Before deploying the solution, ensure you have:

  • Windows Server 2016 or later with PowerShell 5.1+
  • Administrator privileges on the deployment machine
  • Network connectivity to VMware Horizon servers
  • SMTP server details for email alerts (optional)
  • Webhook URLs for Slack/Teams integration (optional)
  • Twilio account for SMS alerts (optional)

🚀 Quick Deployment

  • Download or copy all PowerShell scripts to a temporary directory
  • Open PowerShell as Administrator
  • Navigate to the directory containing the scripts
  • Run the deployment script:
   .\Deploy-Certificate-Automation.ps1 -CreateScheduledTask

This will:

  • Install all components to C:\Scripts\Horizon-Certificate-Automation
  • Create necessary directories and configuration files
  • Set up a scheduled task to run daily at 2:00 AM
  • Generate a deployment summary

⚙️ Configuration

1. Configure VMware Horizon Servers

Edit C:\Scripts\Horizon-Certificate-Automation\Config\servers-config.json:

[
  {
    "Name": "Primary Connection Server",
    "Hostname": "horizon-primary.company.com",
    "Port": 443
  },
  {
    "Name": "Backup Connection Server", 
    "Hostname": "horizon-backup.company.com",
    "Port": 443
  },
  {
    "Name": "Security Server",
    "Hostname": "security.company.com", 
    "Port": 443
  }
]

2. Configure Alert Channels

Edit C:\Scripts\Horizon-Certificate-Automation\Config\alert-config.json:

Email Alerts

"SMTP": {
  "Server": "smtp.company.com",
  "Port": 587,
  "Username": "horizon-monitor@company.com", 
  "From": "horizon-monitor@company.com",
  "UseSSL": true
}

Webhook Alerts (Slack/Teams)

"Webhook": {
  "Slack": "https://hooks.slack.com/services/YOUR/SLACK/WEBHOOK",
  "Teams": "https://company.webhook.office.com/webhookb2/YOUR-TEAMS-WEBHOOK"
}

SMS Alerts (Twilio)

"SMS": {
  "Gateway": "twilio",
  "AccountSid": "YOUR_TWILIO_SID",
  "AuthToken": "YOUR_TWILIO_AUTH_TOKEN", 
  "From": "+1234567890",
  "To": "+0987654321"
}

🧪 Testing

Test Certificate Monitoring

cd "C:\Scripts\Horizon-Certificate-Automation"
PowerShell -ExecutionPolicy Bypass -File "Certificate-Monitor-Improved.ps1"

Test with Different Scenarios

# Test expiring certificate
.\Certificate-Monitor-Improved.ps1 -TestMode "expiring"
# Test expired certificate  
.\Certificate-Monitor-Improved.ps1 -TestMode "expired"
# Test valid certificate
.\Certificate-Monitor-Improved.ps1 -TestMode "valid"

Run Health Check

.\Health-Check.ps1 -Detailed

📊 Monitoring and Maintenance

Check Logs

Logs are stored in C:\Scripts\Horizon-Certificate-Automation\Logs

Log Rotation

The solution automatically rotates logs, but you can manually run:

.\Log-Rotation.ps1

View Alert History

Check certificate-alerts.log for alert history

🛡️ Security Considerations

Secure Configuration

Use the Secure Config Manager to store sensitive information:

.\Secure-Config-Manager.ps1 -Action Set -Key "SMTPPassword" -Value "YourPassword"

File Permissions

The deployment script sets appropriate file permissions automatically

🚨 Troubleshooting

Common Issues

  • Permission Denied Errors
  • Ensure you're running PowerShell as Administrator
  • Check file permissions on the installation directory
  • Network Connectivity Issues
  • Verify network access to VMware Horizon servers
  • Check firewall rules for outbound connections
  • Scheduled Task Not Running
  • Verify the task exists in Task Scheduler
  • Check Windows Event Logs for errors

Manual Execution

If the scheduled task fails, you can manually run:

PowerShell -ExecutionPolicy Bypass -File "C:\Scripts\Horizon-Certificate-Automation\Certificate-Monitor-Improved.ps1"

📈 Certificate Monitoring Levels

The solution monitors certificates and alerts at different levels:

  • 30+ days: No alert (Informational)
  • 15-30 days: WARNING alert
  • 7-15 days: HIGH alert
  • 0-7 days: CRITICAL alert
  • Expired: CRITICAL alert

🆘 Support

For issues with the solution:

  • Check the deployment summary in DEPLOYMENT-SUMMARY.txt
  • Review logs in the Logs directory
  • Run the Health Check utility
  • Verify configuration files in the Config directory
