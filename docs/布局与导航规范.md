# iHangzhou 布局与导航规范（Layout & Nav Standards）

> 配套文档：[docs/UI统一策略.md](UI统一策略.md)（视觉 token 宪法：颜色/圆角/组件/禁止内联 style）
> 本文件管**两项强制布局标准**：① 内容列宽 ② 面包屑导航。改布局/导航前先读两份。
> 定位：本文件是「列宽 + 面包屑」的唯一事实源，新增任何页面必须遵守，Code Review 按此验收。
> 版本：2026-10-18 定稿（基于 playwright 真渲染实测，非印象）

---

## 0. 一句话标准

- **内容列**：桌面（≥1024px）`1180px` 居中；移动 `<1024px` 左右留白 `16px`（`--gutter`）。全站 hero/tabs/卡片/正文**同一条中轴线**。
- **面包屑**：每个页面顶部都有灰底条 `.site-breadcrumb`（头部正下方）。频道页 2 级「首页 › 栏目」，详情页 3 级「首页 › 栏目 › 当前页」。

这两项是用户反复投诉「宽度不对 / 没有面包屑」后定下的硬标准，漂移一律回这里对齐。

---

## 1. 内容列宽标准（唯一事实源）

| 视口 | 内容列 | 说明 |
|---|---|---|
| 桌面 ≥1024px | `max-width: 1180px; margin: 0 auto` | 左右各 `(100vw-1180)/2` 留白 |
| 移动 <1024px | 左右 `16px`（`--gutter`） | 全宽铺满，仅留 gutter |

**硬规则**：
- hero、tabs、卡片、正文块**必须同一条 1180 中轴线**，禁止「hero 居中、下面全宽」这类错位（travel.html 曾翻车：hero 被 `.ch-hero` 约束到 1180，下面 tabs 却全宽 1280）。
- 左右留白**只允许 `--gutter:16px` 一个 token**，禁止写死 `14px`/`32px` 等（首页曾因 14/16/32 三种宽度被投诉）。

**实现（现状）**：
- 频道页：全局规则 `css/style.css` 第 3958 行
  ```css
  /* 频道页(ch-page)桌面统一：内容列 1180 居中，与 .ch-hero 同宽 */
  body.ch-page #pageChannel { max-width: 1180px; margin: 0 auto; }
  ```
  页面只需：`<body class="ch-page">` + 内容根容器 `id="pageChannel"`，桌面 1180 由这条规则自动管，**不写内联 @media**。
- 详情页（SPA）：跟 `.ch-hero` / 详情容器全局规则（桌面 1180）。
- **例外 travel.html**：无 `#pageChannel` 包裹层，1180 靠页内联 `@media (min-width:1024px)` 约束 `.travel-tabs/.travel-section/.travel-tips/.travel-back`（见 travel.html:343）。理想是也包一层 `#pageChannel` 或把内联规则并入全局 `body.ch-page` 体系，消除例外。

## 2. 面包屑标准（强制，全站统一）

统一样式（已定义在 `css/style.css:4347` `.site-breadcrumb`）：灰底 `--bg-alt`、链接 `--primary`、分隔符 `›`（`.sb-sep`，`margin:0 6px`）、当前页 `<b>` 加粗、`padding` 吃 `--gutter`（左右 16px，与内容同边）。

格式：`首页 › 栏目名 [› 当前页]`
- 首页 = 链接 `index.html`；栏目/当前页 = 非链接文本。

### 2.1 频道页：2 级（静态插入）

`首页 › 栏目名`

- 在 `<body>` 直后插入静态 `<nav class="site-breadcrumb">`（layout.js 运行时把 header `prepend` 到 body 首，最终渲染顺序：header → 面包屑 → hero）。
- 当前项（栏目名）用 `<span>`，**不要**包 `<a>`。
- 示例：
  ```html
  <body class="ch-page">
  <nav class="site-breadcrumb">
    <a href="index.html">首页</a>
    <span class="sb-sep">›</span>
    <span>杭州旅游</span>
  </nav>
  ```

### 2.2 详情页（SPA）：3 级（动态，用共享助手）

`首页 › 栏目名 › 当前页`

- **不要手写 nav 串**，统一用 `js/breadcrumb.js`（挂 `window.IHZW`）：
  - `IHZW.breadcrumbHTML(channelTitle, currentTitle[, bleed])` → 返回 HTML 串（适合拼进 render 的 `h` 串，如 place.html 成功/错误态都用它）。
  - `IHZW.prependCrumb(container, channelTitle, currentTitle[, bleed])` → 插到容器首子节点（适合 `container.innerHTML = h` 之后）。
- 栏目名取 `window.IHZ_PAGE.title`；当前页取 `data.name`。
- ⚠️ **顺序铁律**：`prependCrumb` 必须在 `container.innerHTML = h` **之后**调用，否则会被随后的赋值整段覆盖、面包屑消失（district/place 因「之后 / 拼串」才成功）。
- **bleed 出血**：容器自带 `padding:16px` 的详情页（museum / coffee / laozihao / scenic）传 `bleed=true`，面包屑变成 `margin:-16px -16px 0` 向左右/上出血，与内容同边；其余页传 `false`/省略（`0px` 对齐）。
- `<head>` 必须引 `<script src="js/breadcrumb.js?v=最新版本">`，否则 `IHZW` 未定义、守卫静默失败、面包屑不渲染。
- 参考样例：place.html（成功+错误态拼 `breadcrumbHTML`）；tea.html / museum.html（render 后 `prependCrumb`）。

### 2.3 现状（已落地，勿回退）

- 18 个详情页全部接入 3 级：tea / temple / dessert / chaguan / gujian / night-market / tide / route / zhoubian / intangible / museum / coffee / laozihao / scenic / weekend / zhoumo / district / place。
- 10 个频道页接入 2 级：banshi / celebrity / channel / food / history / internet / street / traffic / travel / zhaopin。
- weekend.html 是「列表 + 详情」混合页，保留动态 3 级（按 `?id=` 切换），**不要**再加静态 2 级，否则出现两份面包屑。

## 3. 版本防缓存（改 CSS/JS 必须 bump）

- 所有 `<link href="css/style.css?v=...">` 和 `<script src="js/*.js?v=...">` 带 `?v=YYYYMMDDX`（X = 当日第几次改）。
- 改了样式/脚本就 bump，否则用户缓存旧文件、看到旧布局。
- **bump 用 Python，禁止 shell `sed`/正则 `\1`**（详见 §6 踩坑 5）：
  ```python
  import re
  pages = ['index.html', 'travel.html', ...]  # 全部引用该 css/js 的页面
  for fn in pages:
      t = open(fn, encoding='utf-8').read()
      t2 = re.sub(r'(css/style\.css\?v=)20261018g', lambda m: m.group(1) + '20261018h', t)
      open(fn, 'w', encoding='utf-8').write(t2)
  ```
- 当前版本（截至 2026-10-18）：`style.css?v=20261018g`（全站约 39 处引用同一版本号）。

## 4. 留白 Token

- `--gutter: 16px` 是全站唯一内容留白 token。所有左右内边距用 `var(--gutter)`，禁止写死 `14px`/`32px`/`20px` 等。
- 首页各分节、面包屑、卡片间距统一吃 `--gutter`，保证全站左右边距一致（实测 390/768 视口内容块 left 全为 16，1280 视口全为 50）。

- [ ] 颜色/圆角走 UI统一策略.md 的 token，**不内联 `<style>`、不重定义 `--primary`**。

- [ ] 容器自带 `padding:16px` → `bleed=true`。
- [ ] 列宽跟 `.ch-hero` / 详情容器全局规则（桌面 1180）。
- [ ] 标题字段统一用 `data.name`（与现有 18 页一致）。

## 6. 踩坑清单（别人必看，避免重蹈）

1. **breadcrumb 注入顺序**：`prependCrumb` 必须在 `innerHTML = h` **之后**，否则被覆盖、面包屑消失。district/place 因「之后 / 拼串」才成功。
2. **`<body>` 标签别用正则改**：用正则改 `<body>` 会丢闭合 `>`，整页标签损坏 + nav 误插进 `<script>` 块（曾一次改坏 10 页，全部 `git checkout` 还原重做）。用字符串精确 replace：`s.replace('<body>', '<body class="ch-page">')`。
3. **macOS BSD grep 不支持 BRE `\|` 交替**：`grep "a\|b"` 会静默无输出（假阴性），必须用 `grep -E "a|b"`。曾因此误报「weekend 缺注入」。（本文件作者写诊断时也踩过一次。）
4. **git add 中文/带引号路径**：`git add $(git status --short | awk '{print $2}')` 会把 untracked 中文路径的引号混进来报 `pathspec ... did not match`，改用 `git add -u`（已跟踪文件）或精确列文件名。
5. **版本 bump 的 `\1` 字面量 bug**：`re.sub(r'\1...', ...)` 在某 Python 版本里 `\1` 不展开成捕获组，致 41 页 CSS 链接损坏；一律用 lambda `lambda m: m.group(1) + NEW`。
6. **bleed 出血**：带 `padding:16px` 容器的详情页必须 `bleed=true`，否则面包屑比内容缩进 16px 不对齐。
7. **验证用无缓存浏览器**：district?id=shangcheng「没有面包屑」实测是浏览器缓存旧 HTML，无缓存真渲染有。验证布局/面包屑必须用 playwright 真渲染或强刷（Cmd+Shift+R），**别信肉眼旧页面**。
8. **travel 是列宽例外**：它无 `#pageChannel`，1180 靠内联 `@media`，理想是也包一层 `#pageChannel` 或把内联规则并入全局 `body.ch-page` 体系，别在其它新频道页复制这种例外写法。
